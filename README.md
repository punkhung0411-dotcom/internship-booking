# 🏫 ระบบจองสถานที่ฝึกงาน (Internship Venue Booking System)

เว็บแอปสำหรับ **ให้นิสิตลงทะเบียน/ยื่นคำขอจอง "สถานที่ฝึกงาน" พร้อมแนบไฟล์ Resume**
และ **ให้เจ้าหน้าที่ตรวจสอบ–อนุมัติ / ไม่อนุมัติ**
ข้อมูลทั้งหมดเก็บในฐานข้อมูล **SQLite** ไฟล์เดียว (`data/booking.db`) เปิดดูในเครื่องได้เลย

**จุดเด่นของระบบนี้**
- สถานที่ฝึกงาน **แยกเป็นประเภท**: ฟิตเนส · อคาเดมี่ · โรงเรียน · สถานที่ราชการ (เพิ่มประเภทใหม่ได้)
- นิสิต **พิมพ์ชื่อสถานที่ฝึกงานของตัวเองได้** ระบบจะจำชื่อนั้นไว้ให้เลือกใช้ครั้งต่อไป
- **ไม่มีวันที่และเวลา** — เป็นการลงทะเบียนสถานที่ ไม่ใช่การจองเป็นช่วงเวลา
- ข้อมูลนิสิตใช้เพียง **ชื่อ · นามสกุล · รหัสนิสิต · เบอร์โทรศัพท์** + ไฟล์ Resume

---

## 1) วิธีเปิดใช้งาน (สำหรับผู้ใช้ทั่วไป ไม่ต้องเขียนโปรแกรม)

ครั้งแรกเท่านั้น

1. ดับเบิลคลิกไฟล์ **`setup.bat`** แล้วรอจนขึ้นข้อความ `Setup completed successfully`
2. ดับเบิลคลิกไฟล์ **`run.bat`**

ทุกครั้งที่ต้องการใช้ระบบ

3. ดับเบิลคลิก **`run.bat`** จะมีหน้าต่างสีดำขึ้นข้อความแบบนี้

   ```
   หน้าแรก (เลือกทางเข้า)        : http://127.0.0.1:8000
   สำหรับนิสิต                    : http://127.0.0.1:8000/login
   สำหรับเจ้าหน้าที่ (admin)       : http://127.0.0.1:8000/admin/login
   ให้เครื่องอื่นใน WiFi เดียวกัน  : http://192.168.x.x:8000
   ```

4. เปิดเว็บเบราว์เซอร์ (Chrome / Edge) แล้วพิมพ์ `http://127.0.0.1:8000`
   จะเจอ **หน้าแรกที่ให้เลือก 2 ทางเข้า** (นิสิต / เจ้าหน้าที่)
5. ปิดระบบ = ปิดหน้าต่างสีดำ หรือกด `Ctrl + C`

### 🔗 ทางเข้า 2 ทาง (แยกกันชัดเจน)

| ทางเข้า | ลิงก์ | หน้าตา | ใช้สำหรับ |
|---|---|---|---|
| **นิสิต** | `http://127.0.0.1:8000/login` | โทนเขียว + การ์ดฝั่งซ้าย "สำหรับนิสิต" | สมัคร/เข้าสู่ระบบด้วย **รหัสนิสิต** |
| **เจ้าหน้าที่** | `http://127.0.0.1:8000/admin/login` | โทนม่วงคราม + แถบธง "โหมดเจ้าหน้าที่" | เข้าด้วยบัญชี **admin** เท่านั้น |

- บัญชีนิสิต **ล็อกอินที่หน้าของเจ้าหน้าที่ไม่ได้** และบัญชีเจ้าหน้าที่ **ล็อกอินที่หน้าของนิสิตไม่ได้**
  (ระบบจะพาไปหน้าที่ถูกต้องพร้อมข้อความอธิบาย)
- เมื่อเข้าใช้งานแล้ว สีของเมนูด้านบนจะบอกโหมดทันที: **เขียว = นิสิต**, **ม่วง + แถบ "โหมดเจ้าหน้าที่" = เจ้าหน้าที่**
- ถ้าจำลิงก์ไม่ได้ เปิด `http://127.0.0.1:8000` แล้วเลือกจากหน้าแรกได้เลย

> ⚠️ ต้องเปิด `run.bat` ค้างไว้ตลอดเวลาที่ใช้งาน (ปิดหน้าต่าง = ปิดเว็บ)
> ข้อมูลจริงอยู่ใน `data/booking.db` และไฟล์ Resume อยู่ใน `uploads/`
> **ถ้าย้ายไปเครื่องอื่น ให้คัดลอกทั้งโฟลเดอร์ไป** (หรืออย่างน้อย `data/` + `uploads/`)

### บัญชีทดลองที่เตรียมไว้ให้

| ผู้ใช้ | ชื่อผู้ใช้ | รหัสผ่าน |
|---|---|---|
| เจ้าหน้าที่ (admin) | `admin` | `Admin@1234` ← **ควรเปลี่ยนทันทีที่หน้าโปรไฟล์** |
| นิสิตตัวอย่าง (สมชาย ใจดี) | `65012345` | `Student@123` |
| นิสิตตัวอย่าง (สมหญิง รักเรียน) | `65012346` | `Student@123` |

ข้อมูลตัวอย่างที่มีอยู่: ใบจองฟิตเนส (อนุมัติแล้ว) 1 ใบ, โรงเรียน และ สถานที่ราชการ (รออนุมัติ) 2 ใบ

## 2) วิธีใช้งาน

### นิสิต
1. เปิด `http://127.0.0.1:8000/login` (หรือเลือกการ์ด "สำหรับนิสิต" จากหน้าแรก) → **สมัครสมาชิก** → กรอก **ชื่อ · นามสกุล · รหัสนิสิต · เบอร์โทรศัพท์** และตั้งรหัสผ่าน (≥ 8 ตัวอักษร)
2. เข้าสู่ระบบ → เมนู **+ ยื่นคำขอ**
3. เลือก **ประเภทสถานที่** (ฟิตเนส / อคาเดมี่ / โรงเรียน / สถานที่ราชการ) — ถ้าไม่มีประเภทที่ต้องการ เลือก **"➕ เพิ่มประเภทใหม่ (พิมพ์เอง)"** แล้วพิมพ์ชื่อประเภทเองได้เลย ระบบจะเพิ่มให้ทุกคนใช้ร่วมกันทันที
4. เลือก **ชื่อสถานที่จากรายการเดิม** หรือ **พิมพ์ชื่อใหม่ของตัวเอง** (ระบบจะเพิ่มเข้าประเภทที่เลือกให้อัตโนมัติ)
5. ตรวจ/แก้ไข ชื่อ–นามสกุล และเบอร์โทรศัพท์ (ระบบดึงจากโปรไฟล์มาให้)
6. **แนบ Resume** (จำเป็น, PDF/DOC/DOCX ≤ 15 MB) และแนบเอกสารเพิ่มได้อีกไม่เกิน 2 ไฟล์
7. กด **ส่งคำขอ** → ได้เลขที่คำขอ เช่น `BK2611-0004` สถานะ "รออนุมัติ"
8. ดูสถานะได้ที่เมนู **คำขอของฉัน** และยกเลิกคำขอเองได้

### เจ้าหน้าที่ (admin)
1. เปิด `http://127.0.0.1:8000/admin/login` (หรือเลือกการ์ด "สำหรับเจ้าหน้าที่" จากหน้าแรก) แล้วเข้าสู่ระบบด้วย `admin`
2. หน้าหลักเห็นภาพรวม: คำขอรออนุมัติ, จำนวนคำขอแยกตามประเภท, สถานที่ยอดนิยม
3. เมนู **คำขอทั้งหมด** → กรองตามสถานะ/ประเภท/ชื่อสถานที่ หรือค้นหาชื่อ–รหัสนิสิต–เบอร์โทร–ชื่อสถานที่
4. กด **เปิดดู** → ดูข้อมูลนิสิต + **ดาวน์โหลด Resume** → กรอกหมายเหตุ → **✔ อนุมัติ / ✖ ไม่อนุมัติ**
5. เมนู **สถานที่ฝึกงาน** → ดูรายชื่อแยกตามประเภท, เพิ่มชื่อสถานที่, เพิ่มประเภทใหม่ (เห็นว่าใครเป็นคนเพิ่ม + จำนวนคำขอ), ซ่อน/เปิดใช้สถานที่
6. เมนู **รายชื่อนิสิต** → ดูรายชื่อ/จำนวนคำขอ และระงับบัญชีที่ไม่ควรใช้งาน

### สิ่งที่ระบบตรวจให้อัตโนมัติ
- ❌ ต้องเลือกประเภทสถานที่ และต้องระบุชื่อสถานที่ (เลือกเดิมหรือพิมพ์ใหม่)
- ❌ ต้องแนบ Resume และต้องเป็น PDF/DOC/DOCX ขนาดไม่เกิน 15 MB
- ❌ ไฟล์ว่างเปล่า / ไฟล์ผิดชนิด จะถูกปฏิเสธ
- ❌ นิสิตคนอื่นเปิดดูคำขอของเรา หรือดาวน์โหลด Resume เราไม่ได้ (ขึ้น 403)
- ✅ ชื่อสถานที่ที่พิมพ์ซ้ำกับของเดิม (ประเภทเดียวกัน) จะถูกใช้รายการเดิม ไม่สร้างซ้ำ
- ✅ **ชื่อประเภทที่พิมพ์ซ้ำ (ไม่สนตัวพิมพ์เล็ก/ใหญ่/ช่องว่างเกิน)** จะใช้ประเภทเดิม ไม่สร้างซ้ำ
- ❌ ถ้าเลือก "เพิ่มประเภทใหม่" ต้องพิมพ์ **ชื่อประเภท** และ **ชื่อสถานที่** ด้วย (ประเภทใหม่ยังไม่มีรายชื่อสถานที่)

### 🔐 ความปลอดภัย (Cyber Security) ที่เพิ่มเข้ามา
- **ป้องกันการเดารหัสผ่าน (Brute-force protection)** — IP ที่พิมพ์รหัสผิด **5 ครั้งติดต่อกัน** จะถูกล็อก **15 นาที** (ล็อกแบบ IP-based ใช้ร่วมกันหน้านิสิตและเจ้าหน้าที่)
- **ล็อกอินถูกต้องจะปลดล็อก IP ทันที** — แม้ IP ถูกล็อกอยู่ แต่ถ้ากรอกรหัสผ่านถูกต้อง จะเข้าได้เลยและปลดล็อกอัตโนมัติ
- **Security Headers ทุกหน้า** — `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Content-Security-Policy` (จำกัด script/style/image ให้โหลดจาก self เท่านั้น)
- **Cookie เซิร์ฟเวอร์ปลอดภัย** — `HttpOnly`, `SameSite=Lax`, เซสชันหมดอายุ **8 ชั่วโมง** อัตโนมัติ
- **บันทึกประวัติการเข้าสู่ระบบ** — เก็บ IP, ชื่อผู้ใช้, สำเร็จ/ล้มเหลว, เวลา ไว้ในตาราง `login_logs` สำหรับตรวจสอบย้อนหลัง
- **CSRF Token ทุกฟอร์ม POST** — กันการปลอมแปลงคำขอข้ามเว็บไซต์ (Cross-Site Request Forgery)
- **รหัสผ่านแฮชด้วย scrypt + salt** — ไม่เก็บรหัสผ่านแบบข้อความธรรมดา
- **Parameterized Query ทุกคำสั่ง SQL** — กัน SQL Injection
- **ตรวจสอบสิทธิ์ทุกหน้า** — นิสิตเข้าถึงข้อมูลตัวเองเท่านั้น, เจ้าหน้าที่เข้าถึงข้อมูลทั้งหมด

### ✨ สิ่งที่ปรับปรุงด้าน UX / UI ในรอบนี้
- **หน้าแรกแบบเลือกทางเข้า** — การ์ด 2 ใบ (นิสิต / เจ้าหน้าที่) เห็นชัดว่าต้องเข้าทางไหน
- **แยกธีมสีตามบทบาท** — นิสิตสีเขียว, เจ้าหน้าที่สีม่วงคราม พร้อมแถบ "โหมดเจ้าหน้าที่" เตือนตลอดเวลา
- **เมนูบอกหน้าที่กำลังเปิดอยู่** (ไฮไลต์) และมีไอคอนช่วยจำ
- **ฟอร์มยื่นคำขอมีขั้นตอน 1–2–3** ให้รู้ว่ากรอกถึงไหน
- **ข้อความแจ้งเตือนปิดได้เองใน 6 วินาที** (มีปุ่ม ✕) ไม่บังหน้าจอ
- **ปุ่มส่งฟอร์มกันกดซ้ำ** — ขึ้น "กำลังบันทึก..." ระหว่างรอ
- **ป้ายไฟล์ PDF/DOC** ในรายการไฟล์แนบ อ่านง่ายขึ้น
- **ปุ่มพิมพ์หน้านี้** ในหน้าคำขอ (ซ่อนเมนู/ปุ่มให้อัตโนมัติเมื่อพิมพ์)
- **รองรับจอเล็ก** — เมนูพับได้ ปุ่ม ☰ ตารางเลื่อนซ้าย–ขวาได้
- **หน้าข้อผิดพลาด 403/404 มีปุ่มกลับที่เหมาะสม** ตามบทบาทผู้ใช้

## 3) ดูข้อมูลในฐานข้อมูล SQLite ด้วยตัวเอง

1. ดาวน์โหลดโปรแกรมฟรี **DB Browser for SQLite** → https://sqlitebrowser.org/dl/
2. **Open Database** → เลือกไฟล์ `data\booking.db`
3. แท็บ **Browse Data** เลือกตาราง

โครงสร้าง 5 ตาราง

```
venue_types ─< venues ─< bookings >─ users
                              └─< attachments   (เก็บไฟล์ Resume)
```

| ตาราง | เก็บอะไร |
|---|---|
| `users` | นิสิต/เจ้าหน้าที่: รหัสนิสิต, ชื่อ, นามสกุล, เบอร์โทร, รหัสผ่าน (แฮช), สิทธิ์ |
| `venue_types` | ประเภทสถานที่: ฟิตเนส / อคาเดมี่ / โรงเรียน / สถานที่ราชการ / … + ใครเป็นคนเพิ่ม (นิสิต/เจ้าหน้าที่/ข้อมูลเริ่มต้น) |
| `venues` | ชื่อสถานที่ฝึกงาน + อยู่ในประเภทไหน + ใครเป็นคนเพิ่ม |
| `bookings` | คำขอ: เลขที่, ใครขอ, สถานที่ไหน, สถานะ, หมายเหตุเจ้าหน้าที่ |
| `attachments` | ไฟล์ Resume/เอกสาร: ชื่อไฟล์เดิม + ชื่อไฟล์ที่เก็บจริงใน `uploads/` |

**เริ่มข้อมูลใหม่ทั้งหมด:** ดับเบิลคลิก `reset_database.bat` แล้วพิมพ์ `YES`

> ถ้าเปิดระบบด้วยฐานข้อมูลเวอร์ชันเก่า (แบบที่มีวันที่/เวลา) ระบบจะสำรองเป็น
> `data/booking.db.backup-วันเวลา` ให้อัตโนมัติ แล้วสร้างฐานข้อมูลใหม่ที่ถูกต้องให้เอง
>
> ถ้าเป็นฐานข้อมูลรุ่นก่อนที่มีตาราง `venue_types` แต่ยังไม่มีคอลัมน์ `created_by`
> ระบบจะเพิ่มคอลัมน์ให้เองตอนเปิดโปรแกรม (ข้อมูลเดิมไม่หาย)

## 4) ไฟล์ในโปรเจกต์ (อธิบายสั้น ๆ)

| ไฟล์/โฟลเดอร์ | หน้าที่ |

## 5) ปรับแก้ค่าต่าง ๆ (แก้ในไฟล์ `app.py` / `database.py` แล้วบันทึก ปิด–เปิดระบบใหม่)

| อยากปรับ | แก้ที่ | ค่าเดิม |
|---|---|---|
| พอร์ต (8000) | `app.py` `port = 8000` | 8000 |

## 6) ให้เครื่องอื่นในวง WiFi เดียวกันเข้าใช้

1. เปิด `run.bat` แล้วดูบรรทัด `ให้เครื่องอื่นใน WiFi เดียวกัน: http://xxx.xxx.xxx.xxx:8000`
2. เครื่องอื่นในวง WiFi เดียวกันเปิดเบราว์เซอร์แล้วพิมพ์ที่อยู่นั้น

```powershell
New-NetFirewallRule -DisplayName "Internship Booking 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
```

## 7) นำขึ้นออนไลน์ (Deploy บน Render.com) — **แนะนำใช้ render.yaml (Blueprint)**

วิธีง่ายที่สุด: ไม่ต้องตั้งค่าทีละช่อง ให้ Render อ่าน `render.yaml` เอง

### วิธี A: Deploy ด้วย Blueprint (คลิกไม่ถึง 5 ครั้ง)

1. **Push โค้ดขึ้น GitHub** (ยกเว้น `.venv/`, `data/`, `uploads/` — ดู `.gitignore`)
2. เข้า https://dashboard.render.com → **New +** → **Blueprint**
3. ใส่ URL repo GitHub → **Connect** → Render จะอ่าน `render.yaml` แล้วสร้าง:
   - Web Service: `internship-booking` (Free plan, Singapore region)
   - Persistent Disk: `data-disk` (1 GB, mount ที่ `/var/data`)
   - Environment Variables: `BOOKING_DB_PATH`, `BOOKING_UPLOAD_DIR`, `SECRET_KEY` (สุ่มให้)
4. กด **Apply** → รอ build ~2-3 นาที → ได้ URL แบบ `https://internship-booking.onrender.com`
5. เปิด URL → ล็อกอิน `admin` / `Admin@1234` → **เปลี่ยนรหัสผ่านทันที** (เมนูโปรไฟล์)

> ⚡ **ข้อดี:** Disk คงอยู่ตลอด → SQLite + Resume ไม่หายตอน deploy ใหม่  
> 💤 **ข้อควรทราบ:** Free plan จะ "นอน" หลังไม่มี request 15 นาที → request แรกช้า ~10-20 วิ (cold start)  
>   ไม่ต้องการให้นอน? → อัปเกรดเป็น Starter ($7/เดือน) หรือ ping ทุก 10 นาทีด้วย https://cron-job.org

---

### วิธี B: สร้าง Web Service เอง (ถ้าไม่ใช้ Blueprint)

1. Push โค้ดขึ้น GitHub
2. Render Dashboard → **New → Web Service** → เลือก repo
3. ตั้งค่า:
   | ช่อง | ค่า |
   |---|---|
   | Name | `internship-booking` |
   | Region | `Singapore` |
   | Runtime | `Python 3` |
   | Build Command | `pip install -r requirements.txt` |
   | Start Command | `python -m waitress --host=0.0.0.0 --port=$PORT --threads=8 app:app` |
   | Plan | `Free` |
4. **Add Disk** (Settings → Disks → Add Disk):
   - Name: `data-disk`
   - Mount Path: `/var/data`
   - Size: `1 GB`
5. **Environment Variables** (Settings → Environment):
   - `BOOKING_DB_PATH` = `/var/data/booking.db`
   - `BOOKING_UPLOAD_DIR` = `/var/data/uploads`
   - `SECRET_KEY` = (Generate → ระบบสุ่มให้)
   - `FLASK_ENV` = `production`
   - `RENDER` = `true`  *(เปิด HSTS/HTTPS headers)*
6. **Create Web Service** → รอ deploy
7. เปิด URL → ล็อกอิน `admin` / `Admin@1234` → เปลี่ยนรหัสผ่านทันที

---

### ตรวจสอบหลัง Deploy

| รายการ | วิธีตรวจ |
|---|---|
| ฐานข้อมูลต่อได้ | เปิด `/` แล้วกด "สำหรับนิสิต" → สมัคร/ล็อกอินได้ |
| Resume อัปโหลดได้ | ยื่นคำขอ + แนบไฟล์ → เจ้าหน้าที่ดาวน์โหลดได้ |
| HTTPS บังคับ | URL เริ่มด้วย `https://` และมี 🔒 ใน address bar |
| Security Headers | F12 → Network → Response Headers → มี `X-Frame-Options: DENY`, `Content-Security-Policy`, `Strict-Transport-Security` |
| IP Lockout | พิมพ์รหัสผิด 5 ครั้งติดกัน → ควรขึ้นข้อความล็อก 15 นาที |

## 8) แก้ปัญหาที่พบบ่อย

| อาการ | วิธีแก้ |
|---|---|
| ดับเบิลคลิก `run.bat` แล้วขึ้น "System not installed yet" | ยังไม่ได้รัน `setup.bat` ให้รันก่อน |
| เปิดเว็บไม่ได้ / หน้าเว็บขาว | ปิดหน้าต่างสีดำไปแล้วหรือเปล่า ต้องเปิด `run.bat` ค้างไว้ |
| ขึ้น "ไฟล์แนบใหญ่เกินไป" | ย่อขนาดไฟล์ Resume ให้ต่ำกว่า 15 MB |
| ขึ้น "รหัสความปลอดภัยของฟอร์มไม่ถูกต้อง" | กดโหลดหน้าเว็บใหม่ (F5) แล้วทำรายการอีกครั้ง |
| ล็อกอินแล้วขึ้นว่า "บัญชีนี้เป็นของเจ้าหน้าที่/นิสิต" | เข้าผิดหน้า — นิสิตใช้ `/login` · เจ้าหน้าที่ใช้ `/admin/login` (หรือเลือกจากหน้าแรก `http://127.0.0.1:8000`) |
| เปิด `/admin` แล้วเด้งไปหน้าล็อกอินเจ้าหน้าที่ | เป็นเรื่องปกติ ระบบบังคับให้เข้าด้วยบัญชีเจ้าหน้าที่ก่อน |
| เห็นข้อความแจ้งว่ามีไฟล์ฐานข้อมูลเก่า | ระบบสำรองไฟล์เดิมไว้แล้ว (`data/booking.db.backup-...`) และสร้างใหม่ให้ใช้งานได้เลย |
| ลืมรหัสผ่านเจ้าหน้าที่ | เปิด DB Browser ดูตาราง `users` หรือ `reset_database.bat` เพื่อเริ่มใหม่ (ข้อมูลจะหายทั้งหมด) |
| อยากเริ่มระบบใหม่หมด | ดับเบิลคลิก `reset_database.bat` แล้วพิมพ์ `YES` |
